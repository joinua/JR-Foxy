# JR-Foxy — зашифровані резервні копії

Пакет автоматизації для Ubuntu VPS і Windows 11. Python 3.11+, `age`, OpenSSH.
Бот і схема його бази не змінюються. Сервер не має приватного ключа розшифрування.

## Встановлення

Оновлення пакета 1.1: перевірка ACL працює через Windows API без запуску
PowerShell `-EncodedCommand`. Для окремого `backup_ssh_ed25519` установлювач
прибирає явний дозвіл вбудованої групи Administrators, який може додати OpenSSH.
Решта неочікуваних дозволів зупиняють установлення з точним шляхом і SID.
Ключ не перегенеровується; налаштування антивірусу пакет не змінює.

Передумови: робочий адміністративний SSH-вхід із перевіреним ключем сервера,
`age` на обох машинах, Python на Windows, існуюча папка `D:\JR-Foxy\Backup` та
приватний age-ключ `%LOCALAPPDATA%\JR-Foxy\Keys\backup.agekey`.
Встановлювач не створює і не замінює цей ключ.

Розпакуйте пакет в окрему папку на ПК та виконайте з PowerShell:

```powershell
python "D:\JR-Foxy\BackupSetup\test_windows_acl.py"
# Продовжуйте лише якщо перевірка завершилася OK:
python "D:\JR-Foxy\BackupSetup\install_windows.py" --host <IP-VPS> --admin-key "$env:USERPROFILE\.ssh\jrfoxy_vps_2026"
```

Встановлювач:

1. Перевіряє права папок і наявність NTFS/ReFS ACL. Зберігає існуючі ключі.
2. Створює окремий SSH-ключ `backup_ssh_ed25519` без інтерактивної парольної фрази;
   доступ до приватних файлів обмежений власником і SYSTEM.
3. Переносить підтверджений ключ VPS із власного `known_hosts`, без `ssh-keyscan`
   і без автоматичного приймання нового відбитка.
4. Через чинний адміністративний ключ встановлює серверні файли та додає новий
   ключ до root `authorized_keys` з `restrict` і фіксованим `command`.
   Існуючі ключі зберігаються. Новий ключ не відкриває shell, SFTP, PTY чи тунелі:
   дозволені тільки `status`, `list`, `get <32-символьний ID>`, `create`.
   Загальну конфігурацію SSH та мережеві правила не змінює.
5. Підхоплює початкові архіви та їхні перевірені локальні записи.
6. Реєструє джерело сповіщень і ярлик «JR-Foxy Backup» у меню «Пуск».
7. Через обмежений ключ створює одну нову тестову копію, завантажує її та перевіряє.
   Ця додаткова копія входить у загальний ліміт шести.
8. Лише після успіху вмикає розклади Windows і сервера.

Успішне завершення: `BACKUP_AUTOMATION_READY` і дата наступного запуску.
Якщо крок завершується помилкою, прочитайте її та повторіть встановлення після
виправлення. Ключі та користувацькі шаблони не перезаписуються; власне завдання
Windows має сталу назву й не дублюється. Несумісна зміна адреси або ключів
вимагає свідомого редагування конфігурації. Пакет не вимикає сторонні cron/timer
завдання; раніше створені власні бекап-завдання потрібно перевірити окремо.

## Графік і зберігання

- Сервер: щовівторка 18:00 `Europe/Kyiv`, із переходами на літній/зимовий час.
- Після перезапуску: перевірка простроченого періоду через 2 хвилини.
- Невдала планова копія: повтор щогодини на 05-й хвилині, до успіху.
- Після довгого вимкнення VPS створюється одна поточна копія; минулі дати не імітуються.
- Windows: через 2 хвилини після входу користувача та кожні 30 хвилин у його сеансі.
- ПК завантажує всі відсутні копії з останніх шести, починаючи з найновішої.
- Зберігаються 6 успішних знімків на кожній стороні. Ручні й тестові копії теж рахуються.
- Старі локальні копії видаляються лише після перевірки всього нового пакета.
- При збої копії зберігаються; файл `.part` не вважається готовим бекапом.
- Немає нового архіву — немає сповіщення про успішне завантаження.

Вимкнений, сплячий ПК або вихід із сеансу не дозволяють завантажувати копії чи
показувати сповіщення. Якщо VPS втрачено, ще не завантажені архіви теж втрачені.
За прийнятим рішенням додаткового зовнішнього сховища немає.

## Шляхи

| Об'єкт | Шлях |
|---|---|
| Архіви на ПК | `D:\JR-Foxy\Backup\*.zip.age` |
| Перевірені записи | `D:\JR-Foxy\Backup\state\` |
| Тимчасові дані | `D:\JR-Foxy\Backup\tmp\` |
| Журнали, 90 днів | `D:\JR-Foxy\Backup\logs\` |
| Програми й конфігурація | `D:\JR-Foxy\BackupTools\` |
| Приватний age-ключ | `%LOCALAPPDATA%\JR-Foxy\Keys\backup.agekey` |
| Окремий SSH-ключ | `%LOCALAPPDATA%\JR-Foxy\Keys\backup_ssh_ed25519` |
| Підтверджений ключ VPS | `%LOCALAPPDATA%\JR-Foxy\Keys\known_hosts` |
| Серверні програми | `/opt/jr-foxy-backup` |
| Серверні налаштування | `/etc/jr-foxy-backup` |
| Серверні архіви | `/var/lib/jr-foxy-backup/archives` |
| Серверні стан і журнали | `/var/lib/jr-foxy-backup/state`, `/var/lib/jr-foxy-backup/logs` |

Якщо D недоступний, тільки журнал помилки може зберегтися в
`%LOCALAPPDATA%\JR-Foxy\logs`. Архіви на C автоматично не переносяться.
Не видаляйте приватний age-ключ: новий ключ не розшифрує старі копії.

## Ручні дії на ПК

```powershell
# Перевірити й завантажити нові копії:
python "D:\JR-Foxy\BackupTools\client.py" sync

# Створити нову копію, завантажити та перевірити:
python "D:\JR-Foxy\BackupTools\client.py" create

# Показати серверний і локальний статус:
python "D:\JR-Foxy\BackupTools\client.py" status

# Повторно перевірити конкретний архів:
python "D:\JR-Foxy\BackupTools\client.py" verify --filename "JR-Foxy_....zip.age"

# Призупинити тільки автоматичне завантаження:
Disable-ScheduledTask -TaskName "JR-Foxy Backup"

# Відновити завантаження:
Enable-ScheduledTask -TaskName "JR-Foxy Backup"
```

Серверні дії через звичайний адміністративний SSH:

```bash
systemctl list-timers --all 'jr-foxy-backup*'
systemctl status jr-foxy-backup.service jr-foxy-backup-manual.service
systemctl disable --now jr-foxy-backup.timer jr-foxy-backup-retry.timer
systemctl enable --now jr-foxy-backup.timer jr-foxy-backup-retry.timer
```

Обмежений ключ навмисно не має команд вимкнення, видалення чи довільного запуску.

## Сповіщення

Редагуйте `D:\JR-Foxy\BackupTools\notifications.uk.json` у UTF-8.
Події: `success`, `multiple`, `partial`, `error`; кожна має `title` і `body`.
Підстановки: `{count}`, `{failed_count}`, `{created_at}`, `{latest_created_at}`,
`{scheduled_at}`, `{folder}`, `{filename}`, `{next_retry_at}`, `{reason}`, `{log_path}`.
Невикористовувані в конкретній події значення можуть бути порожніми.

Пошкоджений JSON або невідома підстановка — вбудований шаблон і запис у журналі.
Одна й та сама помилка сповіщається не частіше ніж раз на 24 години; усі спроби
записуються. Після відновлення зв'язку нова помилка може бути показана одразу.
Режим «Не турбувати» й заборона сповіщень Windows зберігають пріоритет.
Збій відображення сповіщення не скасовує вже перевіреної копії.

## Вміст і відновлення

Архів містить `data/jrfoxy.db`, `config/.env`, `config/docker-compose.yml`,
`manifest.json`, `RESTORE.md`. Маніфест містить час, версію/ID запущеного образу,
SHA-256 файлів і кількість записів у таблицях. Увесь ZIP зашифрований `age`.
Побічні тимчасові файли SQLite, ключі, Docker-образи й код до архіву не входять.
Денний кеш `/predict`, який у поточному коді зберігається всередині контейнера,
не входить до погодженого набору «база + налаштування»; це не база профілів.

Перевірка архіву — офлайн відкриття самодостатньої бази, `integrity_check`,
`foreign_key_check`, SHA-256 і звірення таблиць/кількості рядків. Бот при цьому не
запускається, токен не використовується, повідомлення учасникам не надсилаються.

Для відновлення дотримуйтесь `RESTORE.md` всередині архіву: перед заміною робочої
бази зупиніть усіх авторів запису, збережіть поточну базу разом із WAL/SHM для
відкату та не підмішуйте старі журнали до відновленої бази. Версію коду обирайте
за записаним образом/версією, а не автоматично за останнім GitHub main.

## Перевірки й межі підтвердження

Локальні тести перевіряють розклад у Києві, переходи DST, WAL, відсутню базу,
порушення зв'язків, маніфести, заборонені SSH-команди, часткові пакети й ротацію.
Команда: `python -m unittest discover -s tools/backup -p 'test_*.py'`.

Справжні Windows ACL, реєстрація завдання та показ toast перевіряються під час
встановлення на ПК. Сам факт підготовки цього пакета не означає, що розклади
вже запущені: потрібен результат `BACKUP_AUTOMATION_READY` з установлювача.

`test_windows_acl.py` відтворює дозволи SSH-ключа на тимчасовому тестовому файлі,
перевіряє їх виправлення, повторний запуск і відмову при сторонньому дозволі.
Реальні ключі та копії цей тест не відкриває. На Linux три тести Windows
пропускаються; це не підтверджує їх проходження на ПК користувача.

Поточні налаштування з токенами, приватні ключі, архіви й локальні журнали в Git
не додавати. До Git належать тільки код, тести та ця інструкція.
