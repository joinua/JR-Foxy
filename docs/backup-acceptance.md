# JR-Foxy — результати впровадження резервування

Стан зафіксовано 28.09.2026. Реалізація: [PR №44](https://github.com/joinua/JR-Foxy/pull/44), пакет автоматизації 1.3.

## Підтверджено на VPS і Windows

Результати нижче отримано з виводу команд користувача 25–26 вересня та його підтвердження показу сповіщень. Це не нова дистанційна перевірка ПК або VPS 28 вересня.

| Перевірка | Фактичний результат |
|---|---|
| Початковий архів | `SERVER_BACKUP_OK`, `DOWNLOAD_OK`, `LOCAL_BACKUP_VERIFIED` |
| Вміст копії | SHA-256 і розмір збіглися; розшифрування, SQLite `integrity_check`, `foreign_key_check` і кількість записів пройшли перевірку |
| Тимчасові відкриті дані | `PLAINTEXT_TEMP=removed` |
| Реальні дозволи Windows | Усі 6 тестів `test_windows_acl.py` пройдені на ПК користувача |
| Обмежений SSH-ключ | Установлювач створив новий реальний архів, завантажив і перевірив його: `SYNC_OK; new_verified=1` |
| Автоматизація | `BACKUP_AUTOMATION_READY`; серверний і локальний розклади увімкнено |
| Сповіщення | Після виправлення первинної реєстрації Windows користувач підтвердив повідомлення в центрі сповіщень, а потім і роботу банера |

## Чинні параметри

- VPS: щовівторка о 18:00 `Europe/Kyiv`; повтор невдалого періоду щогодини на 05-й хвилині.
- Windows: через 2 хвилини після входу користувача і кожні 30 хвилин у його сеансі.
- Локальні архіви: `D:\JR-Foxy\Backup`; по 6 успішних копій на VPS і ПК.
- Після перерви клієнт завантажує всі відсутні архіви серед останніх шести серверних копій.
- Весь архів зашифровано: база SQLite, `.env`, Docker Compose, маніфест та інструкція відновлення.
- Шаблони повідомлень: `D:\JR-Foxy\BackupTools\notifications.uk.json`.
- Приватні ключі: `%LOCALAPPDATA%\JR-Foxy\Keys`; приватний ключ розшифрування залишається лише на ПК за рішенням власника.

## Межі підтвердження і перша планова перевірка

Перший календарний запуск після встановлення — **29.09.2026 о 18:00 за Києвом**. На дату цього звіту він ще не відбувся. Тривале вимкнення ПК, реальну ротацію семи накопичених копій та аварійні сценарії в робочому середовищі окремо не відтворювали; відповідну логіку перевіряли тестами на тимчасових даних.

Коли після цього часу ПК буде увімкнений, користувач увійде у Windows і буде доступний інтернет, клієнт має завантажити новий архів. Для перевірки без створення додаткової копії:

```powershell
python "D:\JR-Foxy\BackupTools\client.py" status
```

Команда показує стан, але не замінює синхронізацію. За потреби завантаження можна запустити вручну:

```powershell
python "D:\JR-Foxy\BackupTools\client.py" sync
```

Ручний `create` не є доказом спрацювання календарного таймера. Підтвердженням планового запуску будуть новий серверний архів відповідного періоду та успішна локальна перевірка після його завантаження.

Перевіряли самодостатню розшифровану SQLite-копію, без заміни робочої бази й запуску другого бота. Повне аварійне відновлення бота на чистому VPS у цьому прийманні не виконувалося.
